# 数值维护

## 约定

只有 `src/quantity.js` 直接使用本地 `break_infinity.js 2.2.0`。上游来源、SHA-512 与唯一的兼容修改记录在 `src/vendor/break-infinity/README.md`，MIT 许可证随源码保留。游戏仍无构建步骤、在线 CDN 或安装依赖要求。

Quantity 是不可变的数值接口：常用小数值内部仍是原生 Number，大值内部使用冻结的大数对象。业务代码使用同一组 `Q` 函数，不根据大小选择算法。原生路径保持现有小数运算的结果、经典模式和固定帧时序；大值禁止隐式数值转换，漏改的 `+`、`*`、比较或 `Math` 会立即报错。

```js
import { Q } from '../src/quantity.js';

let gold = Q.of('1e400'); // 超出原生范围时必须传字符串
const price = Q.mul('1e399', 2);
if (Q.canAfford(gold, price)) gold = Q.sub(gold, price);
Q.format(gold);          // '8e+399'
Q.ratio(gold, '1e400');  // 0.8，用于 Canvas/HTML 进度条
Q.encode(gold);          // 存档中的规范字符串
```

不要写 `Q.of(1e400)`：JS 会先把字面量变成 Infinity。不要对 Quantity 使用 `Number()`、`Math.floor()`、`+=`、关系比较或 `===`；使用 `Q.of`、`Q.floor`、`Q.add`、`Q.gte`、`Q.eq`。界面使用 `Q.format`；需要完整值时使用 `Q.encode`。

## 哪些量可以增长

`STAT_DEFINITIONS` 的 `quantity: true` 覆盖伤害及副攻击、生命／基地生命、护甲／穿甲、造价／扩容费用、金币奖励、经验、收入、起始金币与治疗。对应加成也使用 Quantity；属性栈的筛选、来源、覆盖→加法→乘法→取整顺序不变。

这些量没有旧的 `1e9` 游戏上限。时间、坐标、移速、射程、攻速、比例、部队数量、队列长度和炮位继续使用原有有界 Number；没有把数值增长变成更快的时钟或更多的实际实体。Legacy、已完成循环、天赋等级仍是原生整数，沿用当前存档的安全边界与精确收支校验。

原生快速路径覆盖绝对值不超过 `1e12` 的有限 Number。解析大数文本时，极小数也可使用大数对象；运算若会原生溢出或乘除下溢则转入大数路径。归一化允许回到小数值。不要依赖内部表示，也不要直接 `structuredClone` 大数对象；复制游戏状态应使用存档的编码／解码，实验配置使用字符串。

## 精度与边界

- 这是大范围近似计算，约 15 位有效数字；`1e400 + 1` 可以仍等于 `1e400`，不保证逐单位精确。现有 Legacy 不使用这种近似账本。
- 库采用十进制尾数与指数。接口要求有限尾数和安全整数指数，指数绝对值最多 `9e15 - 1`；这是技术边界，不是玩法封顶。非法输入、除零、超出范围会报错，不写入 Infinity／NaN，也不悄悄截成假余额。
- `Q.canAfford` 保留原游戏的 `1e-6` 小数支付容差；造价与金币／经验奖励仍先向下取整。生命四舍五入，伤害和收入保持小数。
- 血条用 `Q.ratio(hp, maxHp)`，输出始终在 0–1；不可见的极小比例允许显示为 0。不得先把 hp 与 maxHp 各自转成 Number 再相除。
- `Q.format` 对大值用科学计数，默认保留三位小数并去除末尾零。显示舍入不参与付费、命中或奖励结算。

## 存档 v7

`save.js:mapSessionQuantities` 显式列出成长字段，序列化时统一编码为字符串，例如 `"180"`、`"1.2e+401"`。坐标、时间、ID、计数、Legacy 和布尔值保留原类型；不按字符串外观任意恢复未知字段。

导入要求规范字符串，检查有限性、指数边界、正负与整数约束，以及原有战斗／收支／结算状态一致性。完成解码后运行完整校验，损坏或未知版本仍阻止自动覆盖。保存也检查文件大小，避免生成自己无法读取的记录。

v1–v6 先验证原格式，再按迁移链升级；不重放战斗、奖励、招募或起始资源。v6 基地如果曾被 `1e9` 原型上限截断，新上限恢复后保留已受伤害；已死亡基地仍为 0。已有单位的当前生命、弹药、地面效果、技能与支付快照保持原值。首次成功保存保留原有效记录为备份。

```bash
npm test
node sim/run.js sim/large.example.json
node sim/batch.js --out sim/results/scan.csv
```

`tests/quantity-cases.js` 共用于 Node 和浏览器，覆盖 `1e400` 的算术、消费、退款、护甲与奖励、五时代炮塔及大招、自动购买预留、转场与结算、v6 实际记录迁移、非法导入及模拟 CSV。浏览器 `/tests/` 还检查科学计数显示、血条和队列操作。原有 18 组模拟用于核对小数值平衡，性能比较需同机预热后运行，避免把启动时间当成战斗计算成本。
